# 完整规则文档（跨智能体通用版）

本文档详细描述了与具体智能体无关的资源共享规则体系（共 28 条 + 强制规则0），适用于 WorkBuddy、TRAE、Claude Code、ChatGPT、Codex、Gemini CLI、Cursor 等所有 AI 编程/对话智能体。其中 `<root>` 指代固定共享根目录（默认 `~/.agent-shared/`，可用环境变量 `AGENT_SHARED_ROOT` 覆盖）。

---

## 零、强制约束

### 规则0：固定共享根目录（强制）

所有共享资源必须存放在固定的、与智能体无关的共享根目录下，禁止散落在各智能体私有目录（如 `~/.workbuddy/`、`~/.trae-cn/`、`~/.claude/`、各应用 `Application Support` 等）中。该根目录位于用户主目录，**不属于任何智能体**，是「资源独立存续」的物理基础。详见 SKILL.md 正文。

---

## 一、核心原则

### 规则1：资源独立存续原则

**Skill、MCP、成果文件等资源独立存在，不隶属于任何单一智能体。**

- 卸载/删除任一智能体时，**不得**删除其安装过的 skill、MCP 服务、生成的成果文件
- 智能体 A 安装的 skill，智能体 B 可直接发现并使用，无需重复安装
- 资源的生命周期独立于智能体的生命周期
- 智能体仅作为资源的"使用者"和"安装者"，而非"所有者"

### 规则2：共享资源集中存储原则

**所有可共享的资源集中存放于固定共享根目录，各智能体均可读取，不重复存储。**

- 共享资源存放于 `<root>/`，不嵌入任何智能体的私有目录
- 同一资源（同名同版本）在系统中只保留一份
- 智能体对共享资源默认为**只读**，不得主动删除、修改、移动
- 资源的写入/更新需通过统一的安装/升级流程进行

### 规则2.1：资源强制共享原则

**各智能体的所有资源必须放入共享根目录，不允许私有存储。**

- 智能体安装新 Skill 时，默认安装到 `<root>/skills/` 而非其私有目录
- 智能体产生的模板、配置、成果文件，默认放入共享根目录对应分类
- 智能体私有目录仅保留：对话记忆、临时缓存、锁定配置（`resource-lock.json`）

## 二、资源管理类规则

### 规则3：资源发现与注册机制

**建立全局资源注册表，所有共享资源必须注册，智能体通过注册表发现可用资源。**

- 全局维护一份 `<root>/registry/resource-registry.json`，记录所有已安装的 skill、MCP、模板等资源的元信息
- 新资源安装时自动注册，卸载时（仅手动卸载）注销
- 智能体启动时扫描注册表，了解当前环境中可用的全部共享资源

### 规则4：版本共存与兼容规则

**同一资源的不同版本可共存，智能体按需选择版本，避免版本冲突。**

- 资源目录按 `名称@版本号` 组织（如 `html-report@2.1.0`），支持多版本并存
- 每个智能体可指定使用的版本（锁定版本）或使用最新版本
- 升级资源时不覆盖旧版本，新增版本独立存在
- 版本号遵循 SemVer 规范（主版本.次版本.修订版本）

### 规则5：依赖自动解析规则

**资源间的依赖关系由系统统一管理，智能体使用资源时自动满足依赖。**

- Skill、MCP 可声明依赖的其他 skill 或 MCP
- 安装资源时自动检查并安装缺失的依赖
- 依赖资源同样进入全局共享池，供所有智能体复用
- 依赖冲突时，按"最大兼容版本"策略自动解决

### 规则6：命名空间与命名规范

**资源命名采用命名空间机制，避免不同来源的资源命名冲突。**

- 内置资源：`builtin:<资源名>`（各智能体内置能力经共享暴露）
- 用户自定义资源：`user:<资源名>`（如 `user:my-code-reviewer`）
- 项目级资源：`project:<资源名>`（与具体项目绑定，但仍存于共享根）
- 远程/第三方来源：`remote:<来源标识>/<资源名>`（如 `remote:github/xxx/yyy`、`remote:npm/xxx`）

### 规则11：资源锁定与冲突避免

**智能体可锁定资源版本，防止意外升级导致兼容性问题。**

- 每个智能体维护自己的 `resource-lock.json`，声明其锁定的资源版本
- 未锁定的资源默认使用最新兼容版本
- 锁定版本的智能体不受资源升级影响

### 规则12：资源生命周期管理

**资源的安装、升级、降级、卸载需走统一流程，保证系统一致性。**

- **安装**：通过统一的安装命令，下载/复制资源到共享根目录，注册到注册表
- **升级**：安装新版本，旧版本保留，不影响已锁定旧版本的智能体
- **降级**：切换到旧版本（通过锁定机制实现）
- **卸载**：从注册表移除，文件是否物理删除由用户确认（默认保留文件以防回退）
- **清理**：定期扫描未被任何智能体引用且超过保留期的旧版本，提示用户确认后清理

## 三、资源类型类规则

### 规则7：成果文件共享规则

**智能体产生的有复用价值的成果文件可纳入共享池，供其他智能体引用。**

- 可共享的成果类型：代码模板、配置文件、文档模板、数据集、知识库、项目脚手架等
- 成果文件需经"标记为可共享"后方可进入共享池（默认不共享，保护隐私）
- 共享成果存放于 `<root>/artifacts/`，按类型分类
- 引用成果时使用资源标识符，而非复制文件，确保单一数据源

### 规则8：配置与环境共享规则

**通用配置、环境变量、凭证等可选择性共享，避免重复配置。**

- 全局配置文件存放于 `<root>/config/`，各智能体均可读取
- 凭证类信息（API Key、Token 等）加密存储，需显式授权才能使用
- 共享配置按"配置集"组织（如 `dev-env`、`prod-env`），智能体按需加载
- 智能体私有配置存放于自身目录，不进入共享池

### 规则9：知识库与记忆共享规则

**智能体积累的通用知识可沉淀为共享知识库，跨智能体复用。**

- 通用知识（最佳实践、常见问题解答、领域知识等）可发布为共享 knowledge skill
- 智能体私有对话记忆不共享，保护上下文隐私
- 共享知识需经过"脱敏"和"通用化"处理，去除具体项目和个人信息

### 规则15：MCP / Connector 服务共享规则

**MCP 服务（及各类智能体的等效连接器）全局注册，多智能体可共享同一实例。**

- MCP / Connector 安装后注册到全局注册表
- 同一服务只启动一个实例，多智能体通过连接池共享使用
- 服务的配置（如 API 地址、认证信息）全局存储，各智能体共用
- 智能体可按工具粒度授权使用服务的能力

### 规则16：模板与脚手架共享规则

**项目模板、代码脚手架等通用模板资源全局共享。**

- 模板资源存放于 `<root>/templates/`，按类型分类
- 智能体创建项目时可从共享模板库中选择，无需重复创建
- 用户自定义模板可发布到共享池，供其他智能体使用

### 规则19：插件/扩展级共享规则

**插件作为资源集合整体共享，插件内的 skill、MCP 自动继承共享属性。**

- 插件安装到共享根的相应分类，所有智能体均可启用其中的能力
- 智能体可按需要启用/禁用特定插件的特定能力，而非全有全无
- 插件升级全局生效，但各智能体可锁定插件版本

## 四、技术原则类规则

### 规则10：引用而非复制原则

**智能体使用共享资源时通过引用方式，不做本地副本。**

- Skill 加载时直接读取共享目录中的文件，不复制到智能体私有目录
- 成果文件使用符号链接或路径引用，避免多份拷贝
- MCP / Connector 全局注册一次，多智能体可同时连接使用
- 资源更新时所有引用方自动获得最新版本（除非锁定了版本）

### 规则14：元数据规范

**所有共享资源必须包含完整元数据，确保可发现、可理解、可追溯。**

必选元数据字段：

| 字段 | 说明 |
|------|------|
| `name` | 资源名称（命名空间:名称） |
| `version` | 版本号（SemVer） |
| `type` | 资源类型 |
| `description` | 简短描述 |
| `author` | 作者/来源 |
| `installTime` | 安装时间 |
| `dependencies` | 依赖列表 |
| `compatibility` | 兼容的智能体类型和版本范围 |

## 五、安全与稳定性类规则

### 规则13：安全与权限隔离

**共享资源在安全边界内共享，敏感资源按需授权。**

- 资源分安全等级：公开（所有智能体可用）、受限（需授权）、私有（仅创建者可用）
- 受限资源使用前需用户显式授权，授权记录可审计
- 涉及凭证、密钥的资源使用加密存储和引用机制
- 第三方来源的资源安装前提示安全风险，用户确认后方可安装

### 规则20：故障隔离与降级

**共享资源故障时智能体可降级运行，避免单点故障影响全局。**

- 单个共享资源故障不影响其他资源和智能体的正常运行
- 智能体可配置备选资源（fallback），主资源不可用时自动切换
- MCP / Connector 异常时智能体可降级为无该服务的模式继续工作

### 规则21：远程资源安全审计机制

**从远程拉取第三方 Skill / 资源时，必须执行安全审计，防止恶意代码注入。**

- **触发条件**：从 GitHub / npm / pip / 任意远程 URL 下载资源，或未知来源资源首次加载
- **检查项**：危险函数（`eval(`/`exec(`/`system(`）、未授权外联、敏感路径写入（`~/.ssh/`、`~/.aws/`、系统目录）、凭证窃取、混淆代码、依赖链漏洞、越权声明
- **流程**：隔离区下载 → 静态扫描 + 依赖分析 + 权限审查 → 生成 `<root>/registry/audit-report.json` → 安全移入 / 可疑确认 / 恶意删除并记入 `<root>/registry/blacklist.json`
- **工具**：`bandit`、`eslint-plugin-security`、`safety`、`npm audit`、沙箱试运行

## 六、运营与扩展类规则

### 规则17：资源使用统计与反馈

**记录资源使用情况，帮助发现优质资源和识别废弃资源。**

- 匿名统计各资源的调用频次、成功率、平均耗时
- 智能体可对使用过的资源打分和评价，形成质量参考
- 长期未使用的资源标记为"可能过时"，提示用户确认是否保留

### 规则18：跨设备同步规则

**共享资源可跨设备同步，保持多端一致。**

- 共享资源目录可配置同步策略（本地 / 云端 / 混合）
- 云端同步时对敏感信息加密处理
- 同步冲突时保留所有版本，由用户手动选择合并策略
- 离线环境下本地资源不受影响，联网后自动同步增量

### 规则22：资源贡献激励

- 每贡献一个高质量共享资源，在注册表中记录 `contributionScore`
- 高贡献来源的资源在搜索结果中优先展示
- 定期生成资源共享报告，展示各来源的贡献排名

### 规则23：资源热更新机制

- 共享资源更新时，智能体无需重启即可感知（通过文件监听或注册表版本号对比）
- 锁定版本的智能体不受影响，未锁定的自动热更新
- 热更新失败时自动回退到上一可用版本

### 规则24：资源使用分析看板

- 全局维护资源使用统计数据（调用频次、成功率、平均耗时、错误率）
- 生成可视化看板，帮助用户发现：最常用资源、长期未使用资源、错误率高的资源

### 规则25：跨项目资源继承

- 新项目创建时，可继承已有项目的共享资源配置（`resource-lock.json`）
- 支持项目模板，预定义一套共享资源组合（如"前端开发套件"、"数据分析套件"）
- 一键应用模板，自动安装/锁定所需资源

### 规则26：资源备份与恢复

- 定期自动备份共享根目录到 `<root>/backups/YYYY-MM-DD/`
- 支持按时间点恢复整个共享池或单个资源
- 备份策略可配置（保留最近 N 份 / 保留最近 N 天）

### 规则27：资源权限细粒度控制

- 除了公开/受限/私有三级，支持更细粒度的权限控制：
  - `read-only`：只能使用，不能查看源码
  - `read-write`：可以使用和修改，但不能删除
  - `admin`：完全控制（使用、修改、删除、分享）
- 权限按智能体维度配置，不同智能体对同一资源可有不同权限

### 规则28：资源版本回滚保护

- 资源升级后，自动保留最近 3 个历史版本
- 任何版本回滚操作需记录日志（谁、何时、为何回滚）
- 频繁回滚的资源标记为"不稳定"，提示维护者关注

## 七、执行优先级

1. **用户显式指令** > 规则约定
2. **数据安全与隐私保护** > 共享便利性
3. **系统稳定性** > 资源复用效率
4. **向后兼容** > 版本统一

---

## 八、规则修订机制

- 本规则可根据实际使用情况迭代优化
- 重大变更需用户确认后生效
- 新增规则不影响已存在资源的状态，除非用户主动触发迁移
